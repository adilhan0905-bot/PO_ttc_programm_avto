# CWS — Автономная система предупреждения о столкновениях

Учебный проект на Python, построенный по теме лабораторных работ: анализ видеопотока, обнаружение препятствий, расчёт TTC (Time to Collision), визуальные и звуковые предупреждения, журнал событий, запись размеченного видео, самодиагностика, калибровка камеры, загрузка модели и симуляция передачи критического предупреждения в CAN-шину.

## 1. Что реализовано

- **Обнаружение объектов:** YOLO через Ultralytics/PyTorch.
- **Видеопоток:** видеофайл или веб-камера через OpenCV.
- **TTC:** оценка дистанции по высоте bounding box и расчёт времени до столкновения с учётом скорости автомобиля; дополнительно учитывается наблюдаемое сближение по истории трека.
- **Чувствительность:** 1 / 2 / 3 секунды.
- **Предупреждение:** SAFE / WARNING / CRITICAL, рамка вокруг объекта, звук.
- **Mute:** визуальные предупреждения сохраняются, звук можно отключить.
- **Логирование:** `logs/warnings.csv` и `logs/application.log`.
- **Запись видео:** размеченный MP4 в `recordings/`.
- **Самодиагностика:** проверка OpenCV, модели, каталогов, источника видео и CAN.
- **Обновление модели:** загрузка собственного `.pt` файла.
- **Калибровка камеры:** OpenCV + шахматная доска 9×6, результат сохраняется в `config/calibration.json`.
- **CAN:** по умолчанию учебная симуляция, с возможностью адаптации под `python-can`.
- **UML ЛР №4:** диаграмма компонентов и две диаграммы последовательности в `diagrams/`.

## 2. Соответствие лабораторным работам

### ЛР №1
Основные ВИ «Обнаружить препятствие», «Выдать предупреждение», «Настроить чувствительность», «Записать видео с метками», «Калибровка камеры» и др. отражены в отдельных модулях приложения.

### ЛР №2
Связь `Обнаружить препятствие -> Выдать предупреждение` реализована как обязательная часть обработки опасного TTC; критическое предупреждение может расширяться передачей в CAN при TTC < 1 секунды.

### ЛР №3
Функциональные требования F-01…F-11 представлены рабочими модулями: детектор, TTC, предупреждения, настройки, логирование, запись, самодиагностика, обновление модели, калибровка и CAN-адаптер.

### ЛР №4
Архитектура разложена на компоненты `ui`, `video`, `detector`, `ttc`, `warning`, `logger`, `recorder`, `calibration`, `settings`, `can`; готовые PlantUML-файлы находятся в `diagrams/`.

## 3. Установка Windows

Рекомендуется Python 3.10–3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

Если PowerShell запрещает запуск скриптов, активируйте окружение через `cmd`:

```cmd
.venv\Scripts\activate.bat
```

## 4. Первый запуск

1. Нажмите **Открыть видео** и выберите MP4/AVI/MOV/MKV.
2. Введите скорость автомобиля, например 30 км/ч.
3. Выберите чувствительность TTC: 1, 2 или 3 секунды.
4. Нажмите **Старт**.
5. Для демонстрации включите **Запись** — аннотированное видео сохранится в `recordings/`.
6. При TTC < 1 секунды приложение сгенерирует критическое событие и запишет симулированное CAN-сообщение в `logs/application.log`.

## 5. Про TTC

Это учебная монокулярная оценка, а не промышленная система ADAS. Расстояние вычисляется по модели pinhole: `distance ≈ H * fx / bbox_height`, где `H` — типичная высота объекта. TTC затем оценивается по скорости автомобиля и, при наличии истории, скорости сближения. Параметр FOV установлен по умолчанию в 90° и может быть изменён в `config/settings.json`.

Для реального автомобиля требуются калибровка камеры, точные параметры камеры/геометрии, стабильная оценка скорости и более строгая модель движения объектов.

## 6. Калибровка

Подготовьте папку минимум с тремя фотографиями шахматной доски 9×6. Нажмите **Калибровка** и выберите эту папку. OpenCV сохранит параметры камеры в `config/calibration.json`.

## 7. Тесты

```powershell
python -m unittest discover -s tests -v
```

## 8. Как показать преподавателю

Достаточно продемонстрировать один видеоролик с движущимся объектом, открыть интерфейс, показать bounding box и TTC, изменить чувствительность с 2 на 3 секунды, включить/выключить звук, сделать запись размеченного видео, открыть `logs/warnings.csv` и показать самодиагностику. Это наглядно демонстрирует основные ВИ и функциональные требования проекта.

## 9. Ограничения проекта

Проект учебный. Он не предназначен для управления реальным автомобилем и не должен использоваться как единственная система предотвращения столкновений.
